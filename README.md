# Pi Durable Like Hermes

Самостоятельный ассистент по образцу [Hermes Agent](https://github.com/NousResearch/hermes-agent), но с `@earendil-works/pi-durable` в качестве основного runtime. Цель — один сервис для ВК и Telegram, который работает в личке и группах, хранит память отдельно от истории и восстанавливает незаконченные задачи после падения.

## Что входит в MVP

- **ВК и Telegram:** текстовые сообщения в личке и разрешённых группах. В группах бот отвечает на упоминание или ответ на его сообщение. Сессии разделены по платформе, чату и теме Telegram. Приглашение в группу само по себе не даёт доступ: нужно разрешить и чат, и отправителя.
- **Память по образцу [Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory):** `MEMORY.md` — заметки ассистента до 2200 символов, `USER.md` — профиль пользователя до 1375 символов, доступный только в личке. Это логические Markdown-заметки в SQLite, а не файлы Hermes. Инструмент `memory` добавляет, заменяет или удаляет отдельные фрагменты (`add` / `patch` / `remove`), не переписывая заметку целиком. Несколько правок можно применить одной транзакцией, а лимит проверяется по итоговому тексту. `session_search` ищет по словам через SQLite FTS5 только в текущем чате/теме и по найденному ID открывает обмен с ближайшими соседями. При первом запуске индекс строится по истории, уже сохранённой новым шлюзом. Личные аккаунты ВК и Telegram не связываются автоматически.
- **Восстановление:** входящее событие сохраняется в SQLite вместе с курсором до подтверждения следующему запросу; повтор события не создаёт новый запуск. Pi Durable восстанавливает прерванную сессию или завершает её явной ошибкой после ограниченных повторов. Исходящий ответ хранится отдельно. ВК повторно использует `random_id`, Telegram не повторяет автоматически отправку с неизвестным исходом.

Это не полный порт Hermes: нет импорта старых диалогов, вложений, расписаний и автоматического обновления навыков. По умолчанию бот не имеет доступа к оболочке или файлам хоста.

## Запуск

Node.js ≥ 22.19. Установить зависимости и заполнить `.env` **с отдельными тестовыми токенами**:

```sh
npm ci
cp .env.example .env
chmod 600 .env
npm test
npm run start
```

Можно включить одну или обе платформы. Допустимы ID через пробел или запятую. Пустой список закрывает доступ. Для Telegram нужны ID пользователей и групп, а не `@username`. Для ВК — токен сообщества, его ID и `peer_id` групповых бесед. В настройках сообщества включить сообщения, Long Poll API и событие `message_new`. Права бота и privacy mode определяют, какие обращения Telegram действительно передаст боту.

`data/` содержит приватную историю, заметки и очереди. Храните этот каталог на постоянном диске, не публикуйте и не копируйте выборочно SQLite-файлы работающего сервиса. Для постоянного запуска используйте супервизор с автоперезапуском, одним процессом на каталог данных и одной службой на токен. Статус доставки можно посмотреть без текстов сообщений:

```sh
node --input-type=module -e 'import { DatabaseSync } from "node:sqlite"; const db=new DatabaseSync("data/gateway.sqlite",{readOnly:true}); console.table(db.prepare("SELECT i.platform,o.state,count(*) AS total FROM inbox i JOIN outbox o USING(id) GROUP BY i.platform,o.state").all())'
```

`uncertain` означает, что доставка могла состояться, но сервис не успел зафиксировать подтверждение. Такие ответы не отправляются заново автоматически. При длительном простое мессенджеры могут перестать отдавать накопленные события; локальное восстановление этого не исправляет.

## Проверка

`npm test` покрывает маршрутизацию, списки доступа, изоляцию памяти и повтор доставки. Тест с `SIGKILL` убивает настоящий процесс Pi Durable в середине запроса к подставной модели, запускает обработку снова и проверяет, что после завершения тот же вход не вызывает модель повторно.

Для безопасной проверки существующих ботов, без чтения очередей и отправки сообщений:

```sh
node scripts/check-bots.js /path/to/bots.env
```

Проверка вызывает Telegram `getMe` и ВК `groups.getLongPollSettings`; секреты не выводятся. **Не запускайте два шлюза с одним Telegram-токеном**. Для полноценной проверки с ботами Hermes согласуйте окно переключения или возьмите отдельную пару ботов. Сценарий: написать обоим в личку и группу; проверить упоминание, ответ на сообщение, игнорирование постороннего и отсутствие личной памяти в группе; принудительно остановить новый процесс во время ответа, запустить снова и проверить результат. Для возврата к Hermes сначала остановить новый шлюз.

## Перенос памяти и пробный запуск

Импортируйте только в лички подтверждённых аккаунтов владельца. Команда показывает имена записок, размеры и план, но не содержимое. Не обрезает заметки и не перезаписывает отличающуюся память. Заметки в ВК и Telegram после импорта независимы.

```sh
DATA_DIR="$HOME/.local/share/pi-durable-hermes"
node scripts/import-memory.js "$HOME/.hermes/memories" "$DATA_DIR" "$TG_OWNER_ID" "$VK_OWNER_ID" --dry-run
node scripts/import-memory.js "$HOME/.hermes/memories" "$DATA_DIR" "$TG_OWNER_ID" "$VK_OWNER_ID" --apply
```

Перед запуском выберите модель: личные заметки передаются настроенному поставщику модели в запросах из лички. В групповые запросы эти заметки не включаются.

Для Linux скопируйте `deploy/systemd/*` в `~/.config/systemd/user/`. В `~/.config/pi-durable-hermes/service.env` укажите абсолютные пути `NODE`, `APP_DIR`, `DATA_DIR`. В `bots.env` в том же каталоге укажите модель, токены и списки доступа по `.env.example` (без `DATA_DIR`). Ограничьте права обоих файлов до `600` и выполните `systemctl --user daemon-reload`.

Начало пробы: `systemctl --user start pi-durable-hermes.service pi-durable-hermes-health.timer`. Юнит остановит `hermes-gateway.service` через `Conflicts=`; не включайте обе службы в автозагрузку. При ошибке запуска сразу откатитесь. Проверка очередей каждые пять минут пишет в журнал количество зависших задач (старше 10 минут) и исходящих ответов с неизвестным исходом или ошибкой. Просмотр: `journalctl --user -u pi-durable-hermes-health.service`. Внешних уведомлений нет.

Откат: `systemctl --user stop pi-durable-hermes-health.timer pi-durable-hermes.service`, затем `systemctl --user start hermes-gateway.service`. Новые переписки из пробного периода не переносятся обратно автоматически.

### Резервная копия и проверка восстановления

Остановите новый шлюз перед созданием архива, чтобы получить согласованный снимок всех баз. Храните архивы как приватные данные. Не распаковывайте поверх работающего или существующего каталога данных.

```sh
umask 077
mkdir -p "$HOME/.local/share/pi-durable-hermes-backups"
backup="$HOME/.local/share/pi-durable-hermes-backups/$(date -u +%Y%m%dT%H%M%SZ).tar.gz"
tar -C "$DATA_DIR" -czf "$backup" .
restore=$(mktemp -d)
tar -C "$restore" -xzf "$backup"
node --input-type=module -e 'import {DatabaseSync} from "node:sqlite"; const db=new DatabaseSync(process.argv[1],{readOnly:true}); const r=db.prepare("PRAGMA quick_check").get(); if(r.quick_check!=="ok") process.exit(1);' "$restore/gateway.sqlite"
```

Для восстановления сначала проверьте все извлечённые `.sqlite` и пробный импорт (`--dry-run`), затем укажите проверенный каталог как `DATA_DIR` в `service.env`. Не используйте временный каталог `/tmp` как постоянное хранилище.
